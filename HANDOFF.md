# Передача разработчику

## Текущее состояние

Локальная статическая демонстрация, без запросов к платёжным сервисам, без записи имён и email в хранилище и без рассылок. `config.demo` включён. Выключение флага само по себе не подключает платёжную систему.

## Форма и подарки

Заменить содержимое `#donation-mount` на форму фонда в iframe. Обработчики демонстрационной формы находятся в `app.js`; при её удалении их также нужно удалить/заменить, иначе обращения к отсутствующим элементам остановят скрипт.

После подтверждённого платежа платёжная сторона должна предоставить имя, выбранный **в форме** факультет, ссылку на уже сформированный именной сертификат и статус отправки письма. Сейчас `openGifts(name, facultyId)` демонстрирует это окно; перед реальным запуском убрать демонстрационные подписи и подключить реальные данные, файлы и обработку ошибок.

У сертификата ровно четыре возможных факультета: `renatus`, `nucleus`, `unius`, `vitalis`. Переменная `result` хранит только результат теста для шеринга и не должна определять сертификат. Имя выводится с экранированием. Email нельзя помещать в URL шеринга.

`config.certificates` — временные ссылки для демонстрации интерфейса; общий статический PDF не станет именным автоматически. Персонализированный файл следует генерировать отдельно после успешного платежа. `config.wallpapersZip` — один архив всех обоев.

Если согласован обмен iframe → страница через `postMessage`, проверять точный `event.origin`, `event.source`, тип и схему сообщения. Не считать клиентское сообщение доказательством платежа: оплату подтверждает сервер по механизму платёжного провайдера. Не использовать `targetOrigin: '*'` для имени/email.

Письма отправляет сервер фонда: сертификат, архив обоев (или ссылки на них) и предсказание. Статическая страница не умеет отправлять их самостоятельно. Окно должно отражать реальный статус рассылки, включая ошибку/повторную попытку, а не безусловно утверждать, что письмо отправлено.

## Шеринг

В этом этапе используются предварительные карточки Canvas 1200×630. Готовые файлы на замену задаются в `config.shareImages`. При внешнем источнике изображения для генерации/скачивания нужно настроить CORS, проще хранить файлы на том же домене.

`config.publicUrl` задаётся после выбора домена. На localhost внешние ссылки шеринга скрыты, чтобы пользователь случайно не отправлял неработающий локальный адрес. Сохранение PNG, копирование подписи и системный шеринг остаются доступными.

Кнопки ВК/ОК/Telegram открывают штатный интерфейс передачи ссылки/текста. Они не гарантируют прикрепления PNG. Для картинки есть отдельное скачивание и Web Share с файлом, когда поддерживается. Для MAX используется копирование; автоматическая публикация не реализована.

## Адаптив и доступность

Основные контрольные ширины: 320, 375, 390, 768, 1024, 1440 px. Проверить длинное имя, длинный текст в открытом письме, все ответы, повторное прохождение, секретный вопрос, смену режима шеринга, закрытие диалога Escape и возврат фокуса. При `prefers-reduced-motion` отключены декоративные анимации.

Локальный HTTP-предпросмотр запущен пользователем. Браузерная проверка выполнена; результаты и оставшиеся ограничения перечислены в `QA.md`. Доступ к автоматическому извлечению полного макета Figma ограничен лимитом MCP, поэтому точное попиксельное совпадение всех текстов и деталей не заявляется.
